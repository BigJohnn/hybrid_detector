# 真实采集配对验证：第一轮决策实验

本轮要回答：混合方法在真实图像中是否提供值得进一步投入独立精度实验的信号？
先检查单视图尤其是单锚点视图，再研究多相机联合估计；七相机的强几何约束可能掩盖额外边缘的作用。
本轮工具不复刻历史生产跟踪器，也不把多相机一致性当作独立真值。

- 本轮固定检测器版本，不同时修改假设选择与接受规则。原有失败机制应在当前版本上重新验证。

## 数据恢复与冻结

取回数据后先清点所有采集片段，包括无法处理的片段。核对历史的 2403 个可处理帧和
16821 个相机帧机会，但不为了对齐旧数字而静默删帧。清单以计划观测为分母：缺失文件在
冻结阶段报错并要求修复清单/输入；存在但不能解码的图像或视频帧在运行时记为三组共同失败。
完全缺失的采集必须另列损失原因，不能仅从清单中省略后声称全采集成功率。

每个相机文件必须显式给出分辨率、相机模型、内参、畸变和 `T_base_cam`。
`T_base_cam` 将相机坐标映射到同一个声明的世界坐标；多相机不能都因为默认值而变成单位阵。
采用已有的 `calibration.load_rig` 可将外部标定产品转换成这种独立 JSON，运行时不依赖外部源码。

先按时间均匀抽取每个片段最多 12 个同步帧作为 pilot，抽样索引由帧总数决定，不能按检测结果挑选。
相机只以文件存在、同步和标定匹配为准纳入。记录所有纳入与未纳入片段。
pilot 用于检查管线和决定后续采集；若据此修改算法，后续确认必须使用另外的采集批次。

`group` 表示共享系统误差的采集批次；同一日、同一标定、同一次装配的连续片段应保守地放在同组。
不能把帧号、相机名或随意切出的短视频作为独立组。只有一组时不报告 bootstrap 置信区间；
很少的组即使有区间也只作描述，不宣称稳定的总体推断。

## 三组同图像消融

| 标签 | 假设选择 | 最终测量 |
|---|---|---|
| `anchors` | 锚点几何；移除模型的 facets/edges | 所有已解码锚点角点联合优化 |
| `colour` | 锚点几何加 CAD 面颜色；移除 edges，因此也移除边缘支持分数 | 锚点角点优化 |
| `full` | 当前完整方法 | 锚点角点加边缘法向测量 |

三组使用相同实拍图和一份原始 ArUco 检测结果的独立拷贝，分别选择假设与优化。
不共享任何一组的估计姿态，不用真值或前一帧姿态初始化。默认 `min_anchors=1`，
按共享的原始解码锚点数分层；这样不会预先排除最值得研究的单锚点视图。
另一个 `min_anchors=2` 实验须单独冻结并报告拒绝率。

本阶段固定 `allow_anchor_free=false`。无锚点结果是明确拒绝；无锚点重定位是后续独立实验。
这个消融回答软件中颜色/边缘证据的作用；真实去漆或另一种靶标的硬件对照仍需另外采集。

## 无真值时能做什么

逐视图的估计姿态投影到同一同步帧的其他相机，预测它们已解码的锚点角点，计算留出重投影 RMSE。
其他相机的像素没有参加当前视图的估计，因此它比自身拟合残差更有诊断价值。
仍然共享 CAD 和相机标定，也受同步与角点误差影响，所以只能称为跨视图一致性。
预测落到留出相机背后或不可投影时单列状态；不得只看成功投影的 P90 而忽略这些失败。

同时输出相对纯锚点结果的平移/转角差。差异大不代表更准确，差异小也不证明边缘没有价值。
单相机且无外部真值时，没有留出指标，精度栏目为空。

## 有真值后的主指标

清单中声明参考来源、坐标配准、同步方式与不确定度，按帧提供同世界坐标的 `T_base_target_reference`。
工具区分 `independent`、`proxy`、`synthetic`，所有误差都相对于声明的参考。
把参考类型设为 `independent` 不会自动证明仪器足够准确；参考误差预算要人工审查。

- 对全部计划相机帧报告接受率、失败原因。
- 对有参考且接受的输出报告平移/旋转 P50、P90、P95、最大值。
- 配对增益只比较两种方法都成功且同样可评价的相机帧，并同时给出两组各自的覆盖率。
- 报告接受结果中超阈值的比例，以及全部有参考机会中“成功且在阈值内”的比例。
- 默认 10 mm / 2 deg 仅为可运行的示例阈值；正式实验在冻结前按任务要求设定。
- 以采集组为单位做配对 bootstrap，所有相机、所有连续帧随组一起重采样。
- 按相机、采集组、事前定义的工况和原始解码锚点数分层；不按最终误差挑选“获胜工况”。

决策时先看覆盖率与超限率，再看共同样本的误差收益。若加入颜色主要增加错误分支，
优先研究证据选择；若颜色稳定但加入边缘使尾部变坏，优先研究边缘接受和相关噪声。
若各视图存在一致的距离/方向偏差，先检查标定和制造尺度。
无独立真值时，即使留出残差改善，也只支持安排独立参考实验。

## 使用方法

在仓库根目录运行，不需要安装项目，也不需要外部项目：

```bash
PYTHONPATH=src python -m hybrid_detector.cli.evaluate_capture freeze \
  examples/data/capture_pilot.json --out outputs/capture_pilot/frozen.json
PYTHONPATH=src python -m hybrid_detector.cli.evaluate_capture run \
  outputs/capture_pilot/frozen.json --out outputs/capture_pilot/results
```

安装后也可用 `hybrid-evaluate-capture`。冻结文件和结果目录不覆盖已有内容；后续实验使用新路径。
冻结时记录输入文件 SHA-256、字节数、所有检测参数、软件版本和包源码哈希；
运行前重新核对，输入或代码变化时需要重新冻结。冻结是可复核的本地快照，不等于外部预注册。

原始清单中的路径相对清单文件，冻结路径相对冻结文件。视频无需提前提取为全部图像：

```json
{
  "id": "episode1_frame120",
  "group": "capture_day1",
  "condition": "predeclared_far_oblique",
  "views": {
    "cam13": {"video": "videos/cam13.mp4", "frame_index": 120},
    "cam14": {"video": "videos/cam14.mp4", "frame_index": 120}
  }
}
```

视频索引从零开始；不同相机不一定使用相同索引，必须先依据同步记录建立配对。
多相机清单顶层必须提供 `synchronization` 说明。运行记录解码图像哈希，便于复查编解码差异。
不同机器使用同样版本并不保证逐位相同结果，硬件和平台也记录在结果中。

参考信息形式如下；数值和描述需要替换成实际测量记录，不可照抄示例充当真值：

```json
{
  "reference": {
    "kind": "independent",
    "source": "instrument and immutable reference dataset revision",
    "registration": "independently estimated transform into the declared world frame",
    "synchronization": "measured timestamp alignment and residual timing uncertainty",
    "uncertainty": "translation/rotation uncertainty and registration error budget"
  }
}
```

输出包括：

- `run.json`：冻结清单哈希、环境、协议、有效参数和清点结果。
- `observations.jsonl`：逐相机帧三组结果、原始角点、接受边缘、位姿/协方差、失败原因、耗时和图像哈希。
- `summary.json`：失败率、条件误差、配对比较、按采集组 bootstrap 和各层统计。
- `report.md`：可阅读的结果摘要和解释边界。

评估是冷启动单视图方法比较；角点解码单独计时，图像解码和报告不包含在方法耗时内。
它不代表带跨帧种子的生产速度，也不复现历史七相机联合求解成功率。
全量证据按帧写磁盘；只有统计必要字段保存在内存。中断时保留已写行，但没有最终 summary，
因此不得把中断输出当作完成实验。当前不提供断点恢复，重跑请使用新结果目录。
